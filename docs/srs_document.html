1. INTRODUCTION

1.1 Purpose

This System Requirements Specification (SRS) document details the exact implemented functional and non-functional specifications for ChewCheckers (Smart Nutrition Monitoring Lunchbox for School Children) under SIH Problem Statement SIH25-098. It strictly reflects the physical backend Java microservices codebase, true server port allocations, exact JPA entities, exact Service class names, and true REST API contracts.

1.2 Scope

ChewCheckers is a smartphone-assisted lunchbox monitoring system. Parents and teachers upload photos of school lunchboxes before and after mealtime. A cloud-based AI engine powered by Google Gemini 1.5-flash performs image-based food recognition and nutritional intake estimation (integrated via REST API; requires GEMINI_API_KEY in secrets.properties). The backend calculates specific lunch calorie and protein targets using a configurable allocation ratio (default 0.35 via nutrition.lunch.allocation-ratio=0.35), tracks leftover consumption %, evaluates nutrition_scores, validates lunchbox capacity against targets, and provides a conversational AI Pediatric Nutrition Assistant (AssistantController).

5. FUNCTIONAL REQUIREMENTS

5.1 Parent Onboarding Workflow

Guides parents through a sequential 4-stage setup prior to dashboard activation:

  1. Create Child Profile: Register child demographic and biometric parameters.
  2. Link Class: Associate student to classroom via PUT /api/parent/student/{id}/class using class join code.
  3. Configure Lunchbox Profile: Calibrate physical dimensions, shape, and compartment count.
  4. Dashboard Access Unlocked: Full dynamic insights, meal scanner, and AI assistant enabled.

5.2 Student-Class Linking & Teacher Class Code Management

Enables student-class association (PUT /api/parent/student/{id}/class) and dynamic teacher join code generation (POST /api/teacher/classes/{id}/generate-code).

5.3 Lunchbox Physical & Compartment Modeling

Models physical lunchbox specifications inside Student entity and lunchbox_presets table:

  • boxLength (Decimal, cm)
  • boxWidth (Decimal, cm)
  • boxDepth (Decimal, cm)
  • boxVolume (Decimal, cm³)
  • boxShape (String: Rectangular vs Circular)
  • boxCompartments (Integer: 1, 2, 3, or 4 compartments)

Volume Formulae:

  • Rectangular Box: $\text{Volume} = \text{boxLength} \times \text{boxWidth} \times \text{boxDepth}\text{ cm}^3$
  • Circular Box: $\text{Volume} = \pi \times (\text{boxWidth}/2)^2 \times \text{boxDepth}\text{ cm}^3$

5.4 Lunch Nutrition Target Calculation Engine

Calculates specific lunch calorie and protein requirements using a configurable allocation ratio (default 0.35 via nutrition.lunch.allocation-ratio=0.35):

$$\text{Lunch Calorie Target} = \text{Daily Calorie Target} \times \text{nutrition.lunch.allocation-ratio}$$ $$\text{Lunch Protein Target} = \text{Daily Protein Target} \times \text{nutrition.lunch.allocation-ratio}$$

5.5 Leftover Tracking & Score Evaluation

Processes post-meal leftover image uploads (POST /api/meals/post-meal), records consumption percentages, evaluates nutrition_scores, and handles meal status transitions (PRE_MEAL_UPLOADED $\rightarrow$ PENDING_LEFTOVER_ANALYSIS $\rightarrow$ FULLY_CONSUMED).

5.6 Nutrition Insight Engine

Dynamically computes nutrition insights (GET /api/reports/insights/{studentId}) by evaluating meals, meal_food_items, and nutrition_scores without requiring a physical reports database table.

8. DATABASE SCHEMA (10 PHYSICAL TABLES)

The relational database smart_nutrition_db runs on MySQL 8.0 port 3306 comprising 10 physical relational tables managed by JPA entities:

  • users (User.java): Authentication, Roles, BCrypt Passwords
  • schools (School.java): School Accounts
  • classes (Class_.java): Class Rosters & Class Join Codes
  • students (Student.java): Child Profiles, Biometrics, Calorie/Protein Lunch Targets, Box Dimensions (box_length, box_width, box_depth, box_volume, box_shape, box_compartments)
  • parent_students (ParentStudent.java): Parent-Child Junction Table
  • lunchbox_presets (LunchboxPreset.java): Physical Preset Dimensions
  • meals (Meal.java): Meal Scans, Image Paths & Status Transitions
  • meal_food_items (MealFoodItem.java): AI Breakdown of Identified Food Items
  • nutrition_scores (NutritionScore.java): Consumed vs Target Calculations & Classifications
  • messages (Message.java): Parent-Teacher Conversations & Broadcast Alerts
